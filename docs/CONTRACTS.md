# AirGap Mandates — Shared Contracts (v2.1; v2 frozen at 2026-10-19 13:36 CEST, v2.1 = H0 Safe 3 profile)

Single source of truth for all workstreams. If code and this file disagree, this file wins
until it is changed by a PR that touches `docs/CONTRACTS.md` **and** `contracts/` together (plus a ping to every
WS owner). The design and its reasons live in [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) (v2, authoritative for
*what* and *why*); this file fixes the *exact bytes and APIs*. v1 → v2 changes C-01..C-29 and the v2.1 H0 changes are listed in §12.

Machine-readable versions: `contracts/schemas/*.json` (JSON Schema 2020-12), examples in
`contracts/fixtures/<endpoint>/*.json` and `contracts/fixtures/objects/*.json`, all generated by
`make contracts` (`contracts/build.py`). `tests/test_contracts.py` validates every fixture.

Conventions used everywhere:

- JSON field names: `snake_case`. Enums: `UPPER_SNAKE` for states/kinds, lowercase for decisions/roles.
- Money: **integer minor units** (`amount_minor`, hellers / cents). Never floats anywhere (API, DB, audit, Cedar).
- Currency: `"CZK"` or `"EUR"`.
- Timestamps in JSON/DB: ISO 8601 UTC with `Z`, millisecond precision optional (`2026-10-19T12:05:00Z`).
  Dates: `YYYY-MM-DD`. Device display times: `MM-DD HH:MM` in `Europe/Prague` (`AIRGAP_TZ`). Cedar: epoch seconds (Long).
- IBAN in JSON/DB: electronic format, uppercase, no spaces (`CZ6508000000192000145399`).
- ICO: 8 ASCII digits string.
- Ethereum-style address: `0x` + 40 hex. Stored and compared **lowercase**.
- Signature: `0x` + 130 hex (65 bytes r‖s‖v, v ∈ {27,28}).
- **Nonce.** Every challenge has a displayed nonce of **8 uppercase hex** `^[0-9A-F]{8}$` (`secrets.token_hex(4).upper()`),
  unique among **all** challenges of the deployment (conditional put on `nonces`; regenerate on collision), plus a
  server-side 128-bit `nonce_secret` (32 lowercase hex) that is **never displayed and never returned by the API**;
  the `challenge` leaf carries `nonce_secret_sha256`.
- **Deployment tag.** `AG1/<DEPLOY>`: protocol `AG1`, deployment id from `AIRGAP_DEPLOYMENT_ID` (default `DEMO`,
  1–5 chars `[A-Z0-9]`). It is line 1 of every signed text and part of every `subject_hash`.
- IDs: `mnd_<n>`, `prp_<n>`, `chg_<n>`, `ven_<ico>`, `eml_<16 hex of sha256(raw)>`, `tx_<16 hex>` (§3.2).
  `<n>` comes from atomic counters (`mandate_no`, `proposal_no`, `change_no`), starting at 1.
- Change nonce (KB-JWT freshness, §11): `change_nonce` = 32 lowercase hex (128-bit), audience
  `AG1/<DEPLOY>/changes/<change_id>`.
- Digests: `sha256(canonical_json(x)).hex()` (§7.1), 64 lowercase hex.

## 2. Shared objects

### 2.1 Fact and FactSet

```json
{"id": "F-PSP", "kind": "F", "severity": "WARN", "label": "Payee PSP in SEPA Inst / VoP / licence lists",
 "display_line": "PSP UNKNOWN", "evidence": {"bank_code": "39990", "country": "LT", "found": false},
 "prov": "<64 hex sha256 of the MostlyRight snapshot>"}
```

| field | type | rule |
|---|---|---|
| id | string `^[FH]-[A-Z0-9-]+$` | stable id, table below |
| kind | `"F"` \| `"H"` | F = computed by the executor from data it fetched itself; H = hint from host/agent (UI and log only) |
| severity | `"INFO"` \| `"WARN"` \| `"BLOCK"` | H facts are always `INFO` |
| label | string | human label for the UI (may be non-ASCII; never on the device) |
| display_line | string, ASCII `0x20..0x7E`, **≤ 16 chars** (`safe3-mono-16x4`; 18 on `safe5-mono-18x7`) | device line without prefix; the renderer uppercases and would truncate with `~` (producers must not rely on that) |
| evidence | object, optional | raw inputs for replay; ints/strings/bools/null only |
| prov | 64 hex, optional | SHA-256 of the snapshot the fact was computed from; **required** for every fact whose source is a snapshot |

Fact ids, sources and severities (owner WS-D unless noted). The order of this table is `FACT_ORDER`, the device display
order (§5.4). Values not listed are INFO.

| id | source (snapshot) | values → severity | display_line (≤16) |
|---|---|---|---|
| `F-MANDATE` (WS-A) | active mandate | over cap / no mandate → WARN (step-up) | `OVER MANDATE CAP`, `NO MANDATE` |
| `F-ATTEST` | §11 verifier | k ≥ 2 distinct classes → INFO; break-glass → INFO; `in_network = false` → INFO (`F-CALLBACK` carries the BLOCK); **k < 2, in network and not break-glass → BLOCK** | `ATT 2/3 ERP BANK`, `ATT 3/3 ALL` (full class list would exceed the width), `ATT BREAK-GLASS`, `ATT OFF-NETWORK`, `ATT 0/3` |

H ids: `H-AGENT` (agent's stated reason), `H-UI` (anything else from the host). The executor creates H facts from request
`hints[]` with `display_line` = sanitized hint text (≤ 200 chars, UI only). **H facts never reach the device** and never
change an outcome toward allow (S3).

**FactSet** (`contracts/schemas/factset.json`), returned by `executor.facts.compute.compute(subject, state, now)`:

```json
{"subject_id": "prp_42", "computed_at": "2026-10-19T12:02:00Z", "facts": [Fact],
 "facts_digest": "<64 hex>", "snapshots": {"mostlyright": "<64 hex>", "adis": "<64 hex>"},
 "max_severity": "WARN"}
```
- `facts` = all F facts then H facts, F facts sorted by (`FACT_ORDER` index, unknown ids after by id, `display_line`).
- `facts_digest` = `sha256(canonical_json([f for f in facts if f["kind"] == "F"]))` (H facts excluded).
- `snapshots` = name → SHA-256 of every snapshot used. Names: `mostlyright`, `adis`, `dns`, `whois`, `bank_codes`,
  `registry`, `vop`, `toollog`. `max_severity` over F facts.

**MostlyRight snapshot** (credited in README). Source `s3://ai-hackathon-datasets-422928733782/MostlyRIght/` (the capital I
is the real path): CNB + ESMA licence registers, SEPA Instant and VoP participant lists, EU sanctions (entities),
regulator warning lists. `tools/load_mostlyright.py` (WS-D) loads it into `data/mostlyright/snapshot.sqlite` and writes
`data/mostlyright/snapshot.sha256` (SHA-256 of the sqlite file) — that value is the `prov` of F-PSP, F-WARNLIST,
F-SANCTION and the MostlyRight leg of F-DOMAIN, and appears in `FactSet.snapshots.mostlyright`. Row count [U] (10.5k vs 51k).

### 2.2 Decision

```json
{"decision": "challenge", "rule_ids": ["F-MANDATE", "I-PER", "I-WARN"], "facts": [Fact], "facts_digest": "<64 hex>",
 "mandate_id": "mnd_3", "policy_hash": "<64 hex>", "challenge": ChallengeRef}
```
- `decision`: `"allow"` | `"deny"` | `"challenge"` for proposals; `"deny"` | `"pending"` for payee changes.
- `challenge` present **iff** `decision == "challenge"`. **R0: `deny` ⇒ no challenge** (nothing to approve means nothing on the device).
- `rule_ids`: sorted ascending union of (a) the `@id`s of the determining Cedar `forbid` policies (`P-*` permits are never
  listed) and (b) the F ids of **all** BLOCK and WARN facts present (e.g. a WARN `F-PSP` is listed on a deny). `allow` ⇒ `[]`.
- `mandate_id`: ACTIVE mandate evaluated, or `null`.
- **Proposal decision** (pure `executor.policy.decide.decide()`, Cedar via `cedarpy`, tri-state, §8.1):
  1. Policy set `hard_deny` (Cedar, default-allow base `P-BASE`): any determining forbid (`I-PAYEE` unknown/inactive payee,
     `I-DUP`, `I-AMOUNT` amount ≠ source document, `I-BLOCK` any BLOCK fact) ⇒ **`deny`**.
  2. Else policy set `mandate_allow`: `P-MANDATE` permit and no forbid ⇒ **`allow`** (executed at once, §3.2).
  3. Else ⇒ **`challenge`** (PAY exact-sign step-up). Any WARN fact (`I-WARN`) or F-ANOM ≥ `max_anom` (`I-ANOM`) ⇒ challenge.
  H facts are not in the Cedar context at all (S3).
- **Change decision** (`POST /changes`): `deny` (state `REJECTED`, no challenge) if any F fact other than `F-ATTEST` /
  `F-CALLBACK` is BLOCK at creation; else `pending` (state `PENDING_ATTEST` or `CALLBACK_PENDING`, no challenge yet).
  `F-ATTEST` / `F-CALLBACK` start as BLOCK (`ATT 0/3`, `CALLBACK MISSING`) and turn INFO when satisfied. The CHG challenge is issued only on
  entering `SIG_CLERK`, after policy set `change` (I-ATTEST, I-CALLBACK, I-COOLOFF, I-BLOCK) allows it (§6.1).

### 2.3 ChallengeRef (embedded) / Challenge (`GET /challenges/{nonce}`)

```json
{"nonce": "0C55A1E7", "purpose": "PAY", "role": "clerk", "subject_id": "prp_42", "deployment": "DEMO",
 "profile": "safe3-mono-16x4", "exp": "2026-10-19T13:20:00Z", "text": "AG1/DEMO PAY 42\n...",
 "text_sha256": "<64 hex of sha256(text ascii)>", "subject_hash": "<64 hex>", "width": 16, "lines_per_page": 4,
 "pages": 4, "line_count": 14, "used": false, "created_at": "2026-10-19T13:15:00Z"}
```
- `purpose` = render template: `MANDATE` | `CHG` | `PAY` | `VENDOR_ATTEST` | `ENROLL` | `CHG_REJECT`.
- `role`: bank `clerk` | `treasury`; vendor (hardware issuer profile) `director` | `accountant` | `finance`.
- `subject_hash` = `sha256(canonical_json(subject_object))` where `render.subject_object()` =
  `{v:1, deployment, purpose, role, subject_id, nonce, params, facts_digest, policy_hash}` and `params` = the render
  params minus `subject_hash`, `deployment`, `nonce`, `profile`, `width`. The device shows its first 14 hex on `safe3-mono-16x4` (16 on `safe5-mono-18x7`) (`H` line).
- `safe3-mono-16x4` (default): `width` 16, `lines_per_page` 4, `pages` 1–4. `safe5-mono-18x7`: `width` 18,
  `lines_per_page` 7, `pages` 1–2. `pages` = ceil(`line_count` / `lines_per_page`). ChallengeRef = same object;
  `used`/`created_at` optional.
- `nonce_secret` is stored in `nonces` and never appears here.

```json
{"error": "attestation_insufficient", "message": "ACME s.r.o. 0/3 attestations for new IBAN", "details": {}}
```

## 3. Storage (DynamoDB, eu-central-1)

Table name = `${AIRGAP_TABLE_PREFIX}<name>` (default prefix `airgap-`). On-demand. Types: S, N (boto3 `Decimal` → `int`
at the store boundary), BOOL, M, L. No DynamoDB TTL anywhere (used nonces persist forever).

### 3.2 Atomicity (S5, S6)
- Nonce consumption: conditional update `used = false → true`.
- **Execution = one `TransactWriteItems`**, all or nothing (replaces v1 "append leaf first, then transact"):
  1. `audit` leaf `Put` with `attribute_not_exists(seq)`;
  2. `audit` head `Update` with condition `next_seq = :expected`, set `next_seq = :expected + 1`;
  3. `mandates` `Update` (mandate path only): `ADD spent_minor :a, count :1`, condition
     `status = ACTIVE AND spent_minor <= :max_minus_a AND count < :max_count`;
  4. `ledger` `Put` with `attribute_not_exists(tx_id)`;
  5. `proposals` `Update` to `EXECUTED` (condition `status = PENDING_SIG` or new).
  `tx_id = "tx_" + sha256(f"{auth_ref}|{proposal_id}".encode()).hexdigest()[:16]` where `auth_ref` = `mandate_id`
  (mandate path) or the challenge nonce (step-up). `ClientRequestToken = tx_id + "-" + first 16 hex of the execution leaf hash` (idempotent for identical retries within ~10 min; distinct after a table reset; `IdempotentParameterMismatch` → `IdempotencyMismatch(TxConflict)`).
- **Rail after commit**: write pain.001.001.09 [U version], put its c14n SHA-256 in a `rail_submitted` leaf; pain.002-style
  statuses `ACTC`/`ACSC`/`RJCT`, `DUPL` on resubmission. Recovery re-submits executions that have no `rail_submitted` leaf.
- Non-execution leaves use the same head-conditioned `Put` (steps 1–2) in their own transaction.

### 3.3 Store interface (`executor/store/__init__.py`)
`get(table, key) -> dict|None` · `put(table, item)` · `put_if_absent(table, item, key_attr) -> bool` ·
`update_if(table, key, set_: dict, expect: dict) -> bool` · `increment(table, key, attr, by=1) -> int` ·
`query(table, pk, index=None, sk_range=None, limit=None, reverse=False) -> list[dict]` · `scan(table) -> list[dict]` ·
`transact(ops: list[Op], client_request_token: str | None = None) -> bool` (Put / UpdateIf / IncrementBounded).
`table` is always a **logical** name (`config.LOGICAL_TABLES`); `config.physical_table()` maps it to the physical table
and the backend wraps `main` entity keys as `pk=<entity>#<id>`. **Callers always pass natural keys** (e.g. `get("checkpoints", {"log_id": "audit", "sk": "000000001288"})`); only the backend builds and strips physical `pk`/`sk` (`KEY_SCHEMA` in `executor/store/__init__.py`; `sk` = `str(<sort attr>)` or `"0"`). Audit head = `{"log_id": "head#<log_id>", "seq": 0, "next_seq": N}`; leaf row = `{log_id, seq, event (canonical JSON str), leaf_hash, ts}`; appends use `store.leaf_ops` (leaf Put `attribute_not_exists(seq)` + head update `next_seq == expected`) inside one `store.transact`. Execution leaves are written by WS-A's `tx_execute`, which then calls `executor.audit.checkpoint.maybe_checkpoint(log_id, *, store, settings)` (WS-B). Every `decision` leaf carries `data.inputs = {subject, facts, state}` so `verify_audit --replay` can re-run `decide(**inputs, policy)` (S12).
**`tx_execute(store, *, leaf_event, expected_seq, ledger_row, proposal_id, mandate_debit) -> int`** builds §3.2 steps 1–5,
returns the leaf `seq`, raises `TxConflict` (nothing written) on any failed condition.
Backends: `memory` (dicts + one lock; dev/CI), `dynamo` (boto3; `moto` in CI, real DynamoDB in the demo).

### 4.3 `POST /signatures` verification order (S2, S5)
1. Load challenge by nonce → 404 `not_found`.
2. `role` must equal challenge role → 403 `unknown_signer`.
3. Re-render the text from stored `template` + `params` with the **stored `profile`** via `render.render()`; it must equal
   the stored `text` and its `subject_hash` must equal `sha256(canonical_json(stored subject))` (else 500 `internal_error`).
4. If `displayed_text` given and ≠ re-rendered text → 403 `render_mismatch` (nonce **not** consumed). Diagnostic only.
5. `sig` malformed or recovery fails (`executor.sig.verify_eip191`) → 403 `bad_signature`.
6. Recovered address enrolled and active for `role` (bank roles: `enrolled_signers`, whose `enroll_seq` must point
   at an `enroll` leaf for the same address and role — "enrolled before used", checked online; vendor roles: current
   `vendor_policies`) → else 403 `unknown_signer`.
   6b. For `CHG` in `SIG_TREASURY` and for `MANDATE` 2/2: the recovered address ≠ the first signer → else 403
   `sigs_insufficient`; profile `prod` requires `device = GENUINE` for treasury → else 403 `emulator_not_allowed`.
7. `now >= exp` → 403 `expired`.
8. Consume nonce (conditional) → 403 `nonce_reused`.
9. Purpose guards (FSM §6.1; for PAY re-run `decide()` and require the hard rules) → 403 specific code. Nonce stays consumed.
10. Apply the effect; for PAY the execution leaf, debit and ledger row are one transaction (§3.2).
Every rejection at steps 4–9 appends a `signature` leaf with `accepted:false, error:<code>`.

## 5. Canonical display text (`executor/render.py`, profile `safe3-mono-16x4`)

Shared, deterministic, pure. The executor renders; the host has a copy for preview only (S2). The text is exactly the
bytes the Trezor shows and signs (EIP-191 over `text.encode("ascii")`). The approver device is a **Trezor Safe 3**
(T2B1 physical clerk, T3B1 emulator treasury); its screen was measured at H0 (`docs/device/measurements.md`).

### 5.1 Global rules
- Profile **`safe3-mono-16x4`** (`DEFAULT_PROFILE`): `DEFAULT_WIDTH = 16` columns, `LINES_PER_PAGE = 4` (device page),
  `MAX_LINES = 14` (so `MAX_PAGES = 4`), `BREAK_LINE_MAX = 16`, `MIN_WIDTH[profile] = 16`, title line ≤ 18. Why 16: the
  Safe 3 draws 18 mono columns x 4 lines, but its page-break glyphs take 2 columns on the last line of a page and on the
  first line of the next, so an 18-char line there is split across pages. At width 16 no line can ever reflow; the
  break rule is vacuous. Line 1 is never next to a page break, so the title may use all 18 columns.
- Lines joined with LF, no trailing newline. Every line is printable ASCII `0x20..0x7E`, non-empty, ≤ width (line 1 ≤
  title width). Non-ASCII anywhere → `RenderError("NON_ASCII")` (the Safe 3 draws it as boxes while debuglink reports
  it correctly). Pagination is implicit: the device breaks every `LINES_PER_PAGE` lines and shows CONFIRM (hold, about
  1 s) only on the last page.
- Layout = two logical blocks of 7 lines: **block 1 (lines 1–7) says what the money does; block 2 (lines 8–14) says why
  it is safe and who signs.** Block 1 of a 2-block text is exactly 7 lines. The device pages the text 4 + 4 + 4 + 2.
- Line 1 is the title `AG1/<DEPLOY> <TYPE>[ <no>]`; it is **never dropped or shortened** (too long → `RenderError`).
- **No `[F]`/`[H]` prefixes and no [H] content on the device.** H facts passed in are dropped. Any BLOCK fact →
  `RenderError("R0_BLOCK")` (R0).
- Amounts: integer major units when whole (`125000`), else `125000.50`; no thousands separators.
- Times `MM-DD HH:MM`, `Europe/Prague`. Names: registry name → `TRANSLIT` table (executor-owned, its hash is in
  `policy_hash`) → NFKD, drop combining marks → anything still non-ASCII raises → **uppercase** → truncated to width (16)
  with `~`.
- IBANs: payee and NEW IBAN always **in full**, grouped by 4, balanced wrap (3 groups per line unlabelled at width 16;
  `NEW` + 2 groups per line, continuation indented to the IBAN column). If the labelled NEW IBAN would need more than 3
  lines (34-char IBANs), a `NEW IBAN` label line is followed by the unlabelled IBAN. OLD IBAN only as `..<last4> <YY-MM>`.
  Banks only as `BANK <code> <CC>` (code from the IBAN itself, `BANK_CODE_LEN` per country), never a brand.
- `N <8 hex>` displayed nonce. `H <14 hex>` = first 56 bits of `subject_hash` (§2.3); `P <14 hex>` = first 56 bits of
  `policy_hash` (MANDATE). Security does not rest on these lines; they let a human or auditor cross-check (56 bits is
  still far beyond the v1 32-bit preimage problem, D5).
- Width-driven short forms (deterministic: the long form is used whenever it fits the width, `ROLE_SHORT`):
  `ROLE TREASURY 2/2` → `ROLE TREAS 2/2`; `PAYEES 12 REG V31` → `PAYEES 12 V31`; `OLD ..5399 2024-03` →
  `OLD ..5399 24-03`; `SIGNER ACCT (POA)` → `SIGNER ACCT POA`. Fact lines are truncated to 16 with `~`.
- Other profiles (non-default): **`safe5-mono-18x7`** (Trezor Safe 5: width 18, 7-line pages, 2 pages, `break_line_max`

### 5.3 Page assembly (deterministic)
- **Block 1** = mandatory lines + optional lines chosen in priority order so that block 1 has exactly 7 lines; among the
  possible choices the first (in priority order) whose line 7 is ≤ `BREAK_LINE_MAX` wins. A long IBAN therefore
  displaces optional lines; displaced "carried" lines move to block 2. No valid block 1 → `RenderError` (fail closed).
- **Block 2** = summary line `<b> BLOCK <w> WARN` (PAY, CHG; always first; `b` is always 0, R0), carried lines, fact
  lines, then fixed lines (CHG: `COOLOFF DONE`), `ROLE <ROLE> <i>/<n>`, `N`, (`P`), `H`. Templates without a summary
  (MANDATE, VENDOR_ATTEST): if line 8 would exceed `BREAK_LINE_MAX`, the first line that fits is moved to the front
  (nothing is dropped; vacuous at width 16).
- `check_text()` (S11) splits the text into device pages of `LINES_PER_PAGE` and enforces ≤ `MAX_LINES`, ≤ `MAX_PAGES`
  and, at **every** page boundary, last/first line ≤ `BREAK_LINE_MAX`.

### 5.4 Fact lines, ordering and overflow
- Only F facts; line = `display_line` with whitespace collapsed, uppercased, truncated to width with `~`.
- Display order: position of `id` in `FACT_ORDER` (§2.1 table order, including `F-AMOUNT-DOC` after `F-DUP`; unknown
  ids after, by id), then `display_line`.
- Fact slots = 7 − (summary + carried + fixed lines). If facts overflow, the most severe are kept (WARN before INFO, then
  display order), shown in display order, and the last slot becomes `+N MORE 0 BLOCK` (N = omitted facts). The summary
  always counts all F facts. Dropping never changes the decision; the full list is in the payload and the audit log.
- **Pinned facts (CHG):** `CHG_PINNED_FACTS = ("F-ATTEST", "F-CALLBACK")`. On a CHG screen F-ATTEST (`ATT k/3 ...` or
  `ATT BREAK-GLASS`) is always shown and never folded into `+N MORE`: it is what the human confirms. F-CALLBACK is kept
  next when there is room (on any screen that can exist it reads `CALLBACK OK`, R0). If the pinned line plus the
  overflow line need room, a carried `OLD ..xxxx` line yields its slot.

## 6. Signatures and enrolment

- Primitive: **EIP-191 `personal_sign`** over the canonical text (Trezor `ethereum.sign_message`, hold to confirm).
  One path per approver: `m/44'/60'/0'/0/i`. Used purely as a message-signing primitive: no chain, no gas, no funds.
- Verify (pure, `executor/sig.py`): `verify_eip191(text: str, sig: str) -> str` = lowercase address via
  `eth_account.Account.recover_message(encode_defunct(text=text), signature=sig)`. Never trust the host's address.
- Signer (host, WS-C): `host.signer.SignerDriver.sign(challenge: dict, key_ref: str, timeout: float) -> Approval`
  (`Approval` = `{nonce, address, sig, displayed_text, device}`); drivers `usb` (physical Trezor Safe 3 over WebUSB,
  **clerk**; matches WebUSB only, never a running emulator; no Bridge) and `udp` (trezor-user-env Safe 3 emulator
  T3B1 `udp:127.0.0.1:21324`, **treasury**, labelled EMULATOR). Role paths: clerk `m/44'/60'/0'/0/0`, treasury
  `m/44'/60'/0'/0/1`. On timeout the host sends `Cancel` (device returns home) and raises `TimeoutError`.
- **Enrolment ceremony** (`tools/enroll.py`, ARCHITECTURE §3.3): `authenticate_device` (Optiga chain, physical device
  only), `GetFirmwareHash(challenge)` vs the official release, `get_address` per role path, EIP-191 over the `ENROLL`
  template. The tool (never the host) sets `device` = `GENUINE` | `EMULATOR` and records `device_model`,
  `firmware_version`, `cert_chain_sha256`, `fw_hash`, `enroll_sig` in `enrolled_signers` and an `enroll` leaf.
  Profile `prod` refuses EMULATOR keys for treasury (`emulator_not_allowed`); `demo` allows them with a visible label.
- Passphrase policy: the physical device keeps passphrase protection **on**; the host always opens the standard
  (empty-passphrase) wallet and **never types a passphrase** (with `passphrase_always_on_device=True` it is entered on
  the device). A different passphrase derives a different, unenrolled address and therefore fails safe
  (403 `unknown_signer`). Seed generated on-device; seeds never in the repo (`*.seed` git-ignored). Attestation proves
  a genuine device at enrolment only (honest limit).
- Vendor roles (`director`, `accountant`, `finance`) for the hardware issuer profile live in `vendor_policies`.

### 6.1 Payee-change state machine v2 (`executor/change/machine.py`)

States: `PENDING_ATTEST, CALLBACK_PENDING, COOLING, SIG_CLERK, SIG_TREASURY, ACTIVE, REJECTED, EXPIRED`.
Terminal: `ACTIVE, REJECTED, EXPIRED`. The v1 transient states (`REQUESTED`, `FACTS_DONE`, `ATTESTATION_CHECK`,
`TRIPWIRE_SENT`, `CALLBACK_CONFIRMED`, `CALLBACK_DENIED`) are now **`change_event` leaves**, not states.
A **tripwire** notification goes to the contact registered at enrolment on **every** create. Inbound calls are never an input.

| from | to | event (`ChangeEvent`) | guard |
|---|---|---|---|
| (create) | REJECTED | `CREATE` | any F BLOCK other than F-ATTEST / F-CALLBACK: F-DOMAIN lookalike, F-DKIM fail, F-VOP NMTC, F-WARNLIST / F-SANCTION hit, F-VAT unreliable payer |
| (create) | PENDING_ATTEST | `CREATE` | vendor `in_network` (pinned issuers); tripwire sent |
| (create) | CALLBACK_PENDING | `CREATE` | `¬in_network` (break-glass by default); tripwire + callback code out-of-band to the **registered** phone |
| PENDING_ATTEST | COOLING | `VC_RECEIVED` | ≥ 2 valid VCs from **distinct pinned issuer classes**, KB-JWT `nonce == change_nonce`, `aud == AG1/<DEPLOY>/changes/<id>`, `iat` ≤ 15 min old; no BLOCK after recompute; `not_before = now + cooling` |
| PENDING_ATTEST | CALLBACK_PENDING | `BREAK_GLASS` | from the **vendor-portal role** (supplier declares key loss); `break_glass = true`; prod cooling 72 h |
| CALLBACK_PENDING | COOLING | `CALLBACK_CONFIRM` | code hash matches, not expired, attempts ≤ 3; no BLOCK after recompute |
| CALLBACK_PENDING | REJECTED | `CALLBACK_DENY` / `CALLBACK_ATTEMPTS_EXCEEDED` | — |
| COOLING | SIG_CLERK | `COOLING_ELAPSED` (Scheduler `at(not_before)` or lazily on read) | `now ≥ not_before` and policy set `change` allows (I-ATTEST, I-CALLBACK, I-COOLOFF, I-BLOCK); a fresh clerk CHG challenge is issued |
| SIG_CLERK | SIG_TREASURY | `CLERK_SIGNED` | enrolled clerk; fresh treasury challenge (same body, `ROLE TREASURY 2/2`, new nonce) |
| SIG_TREASURY | ACTIVE | `TREASURY_SIGNED` | enrolled treasury, address ≠ clerk; prod: `device = GENUINE`; `registry` updated (+`registry_version`) in the same transaction |
| any non-terminal | REJECTED | `TRIPWIRE_NOT_US` (registered contact) / `VC_REVOKED` / `CLERK_REJECT_SIGNED` (signed `CHG_REJECT`) | logged with actor |
| any non-terminal | EXPIRED | `EXPIRE` (lazily) | `now ≥ expires_at` (`created + AIRGAP_CHANGE_TTL_SECONDS`) |

- `F-ATTEST` is computed in PENDING_ATTEST: fewer than 2 distinct classes is **BLOCK**, so no challenge is issued (R0).
- All other transitions are forbidden (`ForbiddenTransition`, S4). Every transition appends a `state_transition` leaf;
  every intermediate step (facts computed, tripwire sent, callback issued, VC received/rejected, break-glass) a `change_event`.
- A CHG signature on a stale/unknown challenge or in a state ≠ SIG_CLERK/SIG_TREASURY → nonce consumed, 403 with:
  in-network and < 2 VCs → `attestation_insufficient`; off-network/break-glass not confirmed → `missing_callback_attestation`;
  COOLING → `cooling_off`; treasury in SIG_CLERK or same address → `sigs_insufficient`.
- `ALLOWED_TRANSITIONS`, `INITIAL_STATES` and `EVENT_TRANSITIONS` in `machine.py` are contract data.

## 7. Audit log (`executor/audit/`)

### 7.1 Canonical JSON (= RFC 8785 JCS for our domain)
`json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False).encode("utf-8")`.
Floats are forbidden (raise). Integers, strings, bools, null, lists, objects with ASCII keys only. Under these
restrictions the output is byte-identical to RFC 8785 JCS (`tests/test_canonical.py` checks JCS vectors).

### 7.2 Leaf event v2 (`contracts/schemas/audit_event.json`)
```json
{"v": 2, "log_id": "audit", "seq": 37, "ts": "2026-10-19T12:34:56.789Z", "type": "decision", "actor": "executor",
 "subject_id": "prp_41", "data": {...}, "policy_hash": "<64 hex>", "inputs_digest": "<64 hex>",
 "facts_digest": "<64 hex>", "hints_digest": "<64 hex>"}
```
`policy_hash`, `inputs_digest` (= digest of the exact `decide()` inputs), `facts_digest` (§2.1) and `hints_digest`
(= digest of `hints[]`) are **required on decision-relevant events** (`proposal`, `facts`, `decision`, `challenge`,
`signature`, `execution`, `change_event`, `state_transition`) and `null` elsewhere.
`actor`: `executor|agent|host|vendor_portal|ingest|witness|tools|issuer|checkpointer|rail|scheduler|auditor`.
`seq` monotonic per `log_id`, starts at 0, no gaps.

| type | data (required fields) |
|---|---|
| `enroll` | `address, role, label, device (GENUINE\|EMULATOR), device_model, firmware_version, cert_chain_sha256, fw_hash, derivation_path, enroll_sig, active (bool)` — the latest `enroll` leaf per (address, role) is authoritative; deactivation = a new `enroll` leaf with `active: false` (`executor.store.signers.deactivate()`) |
| `ingest` | `email_id, sha256, from_domain, received_at, dkim` |
| `challenge` | `nonce, nonce_secret_sha256, purpose, role, subject_id, deployment, profile, text_sha256, subject_hash, exp, template, params` (`template` + exact render `params` so the offline verifier re-renders the signed text and checks `text_sha256` and the EIP-191 signature, S2) |
| `mandate_signed` | `mandate_id, mandate_no, signer_address, role, nonce, sig_index, sig_total, status, fields{...}` |
| `proposal` | `proposal_id, invoice{...}, hints[...]` (agent input verbatim) |
| `facts` | `subject_id, facts[Fact], snapshots{}` |
| `decision` | `subject_id, decision, rule_ids, mandate_id` |
| `state_transition` | `change_id, from, to, event, reason` |
| `change_event` | `change_id, event (facts_computed\|tripwire_sent\|callback_issued\|callback_confirmed\|callback_denied\|vc_received\|vc_rejected\|break_glass\|cooling_scheduled), detail` |
| `signature` | `nonce, purpose, role, signer_address (or null), text_sha256, sig, accepted, error (or null)` |

### 7.3 Hashing, checkpoint, witness
- Hashing unchanged (RFC 6962/9162 §2.1): `leaf_hash = SHA256(0x00 || canonical_json(event))`, node
  `SHA256(0x01 || l || r)`, empty root `SHA256("")`, `k` = largest power of two `< n`; inclusion/consistency proofs per
  RFC 9162 §2.1.3–2.1.4. Hex lowercase in JSON, base64 (std, padded) inside notes.
- Attestation log = same primitives, `log_id = "attest"`; leaf data carries salted commitments
  `SHA256(canonical_json(body) || commit_nonce_128)` — never a bare IBAN hash.
- **Checkpoint** = C2SP [tlog-checkpoint](https://c2sp.org/tlog-checkpoint) inside a [signed-note](https://c2sp.org/signed-note),
  emitted every `AIRGAP_CHECKPOINT_EVERY_N_LEAVES` (10) leaves or `AIRGAP_CHECKPOINT_MAX_SECONDS` (30):
  ```
  airgap.example/demo/audit
  1288
  <base64 root hash>
  policy sha256:<policy_hash hex>
  code sha256:<lambda CodeSha256 hex> pcr0 -

  — airgap.example/demo/audit <base64(keyid4 || ed25519 sig)>
  — airgap.example/demo/w1 <base64(keyid4 || timestamp8 || ed25519 sig)>
  ```
  Origin `<AIRGAP_LOG_ORIGIN>/<log_id>` (default `airgap.example/demo`). Log signature: Ed25519 (note type `0x01`),
  key id = `SHA-256(name || 0x0A || 0x01 || pubkey)[:4]`, signed message = the note body (all lines, each ending LF).
  Verifier key string `name+<keyid hex>+<base64(0x01 || pubkey)>` (Go `sumdb/note`). Key: **KMS Ed25519**
  (`ECC_NIST_EDWARDS25519`, `ED25519_SHA_512`, MessageType RAW [U names]); fallback 1: local Ed25519 key in Secrets
  Manager (checkpointer role only); fallback 2: ECDSA P-256 (note type `0x02`, the stock-Go claim is then dropped).
- **Witness** = C2SP [tlog-witness](https://c2sp.org/tlog-witness): `POST /witness/add-checkpoint`, body `old <size>\n`,
  ≤ 63 base64 consistency-proof lines, an empty line, then the checkpoint. 200 = cosignature line(s)
  ([tlog-cosignature](https://c2sp.org/tlog-cosignature) type `0x04`: key id = `SHA-256(name || 0x0A || 0x04 || pubkey)[:4]`,
  signed message `cosignature/v1\ntime <t>\n` + checkpoint body incl. extension lines, signature line
  `base64(keyid4 || uint64be(t) || sig)`, verified against torchwood v0.10.0; cosigner vkey
  `name+<keyid(0x04) hex>+<base64(0x04 || pubkey)>`, parsed by `torchwood.NewCosignatureVerifier`); 400 old size >
  checkpoint size, 409 stale (`text/x.tlog.size` body), 403 bad signature, 404 unknown origin, 422 bad proof.
  Size check and persistence are **one** conditional write on `witness_state`. W1 never writes the audit log (S7: the witness is a separate trust domain): it returns the refusal, and the **checkpointer/relay** appends `witness_refusal`. W1 trusts the log key via a pinned vkey (`AIRGAP_W1_LOG_VKEY`), not via KMS access to the log key.
  W1 = witness λ (own role, own KMS key, own table); W2 = unmodified litewitness on its own EC2 instance and key
  (`AIRGAP_W2_URL`), "independent supervisor witness (simulated operator)". The W2 relay posts W2's cosignature back via row 22b (it has no audit access; W2 refusals go to relay stdout/exit code only). Quorum: `log AND (W1 OR W2)`. Scheduler (WS-E): EventBridge every 30 s → `log.tick()`, every 300 s → `log.anchor()`.
- **Storage**: leaves in DynamoDB `audit`; every checkpoint and leaf batch also to S3 `AIRGAP_ANCHOR_BUCKET` with
  **Object Lock GOVERNANCE, 1-day retention** (never COMPLIANCE; teardown needs `s3:BypassGovernanceRetention`).
  RFC 3161 is optional and off by default (`AIRGAP_TSA_URL=off`).

### 7.4 Export and receipt
`audit_export.response`: `{log_id, redacted, leaves: [{seq, event, leaf_hash}], checkpoints: [note text with cosignatures],
pubkeys: {log, w1, w2} (note verifier keys), approvers: [{address, role, device, enroll_seq}],
policies: {<policy_hash>: {cedar_policies_text, cedar_schema, translit_table, fact_severity_table, params, policy_v} (= `policy_material()` verbatim, so sha256(canonical_json(material)) == policy_hash)},
snapshots: {<sha256>: <uri>}, render_profile: "safe3-mono-16x4"}` (schema: `safe3-mono-16x4` | `safe5-mono-18x7`). `redacted=1` replaces IBANs with commitments.
**Receipt** (`receipt.json`, self-contained, tlog-proof style): `{tx, entry (the execution event), seq, leaf_hash,
tree_size, inclusion_proof [hex], checkpoint_note (with cosignatures), key_ids {log, w1, w2?}, vkeys {log, w1, w2?}}`;
shown as a QR code; verifies alone with `tools/verify_audit.py --receipt`.

### 7.5 Offline verifier (`tools/verify_audit.py`, TB5)
`verify(bundle: dict) -> Report` (`Report.ok`, `Report.problems: list[str]`, `Report.checked: dict[str, int]`) checks:
leaf hashes, no seq gaps, roots vs checkpoints, inclusion and **consistency** across all checkpoints, log + W1 + W2
signatures (quorum configurable), for every accepted signature **re-render** with `render.py` and recover the signer
(enrol leaf + role), **replay `decide()`** at the logged `policy_hash` (S12), 2/2 distinctness, cooling-off ordering,
ledger ↔ execution leaves. `tools/noteverify/` = 30-line Go binary on unmodified `golang.org/x/mod/sumdb/note`.

## 8. Invariants

### 8.1 Policy rules (Cedar, `executor/policy/cedar/`, owner WS-A)

Rules are Cedar policies whose `@id` annotation **is** the rule id. Three policy sets (files), evaluated with `cedarpy`:
`hard_deny.cedar` (payments, deny), `mandate_allow.cedar` (payments, allow vs step-up), `change.cedar` (may a CHG
challenge be issued). Schema: `schema.cedarschema.json` (entities `Mandate`, `Payee`, `Change`; actions `pay`,
`issue_chg_challenge`; **context = [F] only**). `cedarpy` reports determining policies as `policy<N>` in file order;
`executor.policy.rules.policy_ids(text)[N]` is the matching `@id`. A pure-Python fallback (`rules.py`, same ids) is
allowed if the cedarpy diagnostics prove awkward (decision Mon 16:00). There is one source of truth.

| id | set | rule | outcome |
|---|---|---|---|
| I-PAYEE | hard_deny | payee known, ACTIVE, with an ACTIVE IBAN in `registry` | deny |
| I-AMOUNT | hard_deny | invoice amount and details equal the provenance-hashed source document (F-AMOUNT-DOC not BLOCK; mirrors the tools-λ `T-AMOUNT-MISMATCH`) | deny |
| I-DUP | hard_deny | same normalized `invoice_no` for the vendor, or (vendor, amount ±50 bp, issue_date ±3 d) already EXECUTED/PENDING_SIG | deny |
| I-BLOCK | hard_deny, change | any F fact BLOCK | deny / no CHG challenge |
| I-MANDATE | mandate_allow | an ACTIVE mandate with the current `policy_hash` | challenge |
| I-EXP | mandate_allow | `valid_from ≤ now < valid_until` | challenge |
| I-PER | mandate_allow | `amount_minor ≤ max_per_payment_minor` | challenge |
| I-BUDGET | mandate_allow | `spent_minor + amount_minor ≤ max_total_minor` | challenge |
| I-COUNT | mandate_allow | `count + 1 ≤ max_count` | challenge |
| I-REGISTRY | mandate_allow | payee in the registry snapshot pinned by the mandate | challenge |
| I-VOP | mandate_allow | F-VOP code ∈ `require_vop` | challenge |
| I-ANOM | mandate_allow | F-ANOM score < `max_anom` (default 40) | challenge |
| I-SPLIT | mandate_allow | the vendor already has ≥ 1 executed payment in the last 24 h **and** that 24 h sum + amount > `max_per_payment_minor` (a single over-cap payment is `I-PER` only, never a split) | challenge |
| I-Z | mandate_allow | robust z-score (median/MAD) of amount vs vendor history ≤ 3.5 (`z_threshold_milli: 3500`) | challenge |
| I-WARN | mandate_allow | no F fact WARN | challenge |
| I-ATTEST | change | in-network, not break-glass ⇒ ≥ 2 VCs from distinct pinned classes | no CHG challenge (R0) |
| I-CALLBACK | change | off-network or break-glass ⇒ callback confirmed | no CHG challenge |
| I-COOLOFF | change | `now ≥ not_before` | no CHG challenge |
| I-NONCE | — | challenge used once (enforced in `/signatures`) | 403 `nonce_reused` |

`policy_hash` = `sha256(canonical_json(policy_material()))` with
`policy_material() = {cedar_policies_text, cedar_schema, translit_table, fact_severity_table, params, policy_v: 2}`
(`executor.policy.rules`; `cedar_policies_text` = the three files concatenated in the order above, LF-joined).
Any change to a policy, the schema, the translit table or the severity table changes the hash. A mandate whose
`policy_hash` ≠ the current hash fails I-MANDATE. Normalized invoice no: uppercase, strip leading zeros of numeric
runs, then strip non-alphanumerics (`FV-2026-0412` → `FV2026412`).

## 11. Supplier attestation (SD-JWT VC, WS-D)

- **Format**: `PayeeBindingAttestation` = SD-JWT VC (RFC 9901 SD-JWT; SD-JWT VC draft), `vct = "urn:airgap:payee-binding:v1"`,
  ES256, compact `<issuer-jwt>~<disclosure>~...~<kb-jwt>`. Issuer JWT claims: `iss`, `vct`, `iat`, `exp`, `cnf.jwk`,
  `_sd` (digests), `ico`, `change_id`, `valid_from`, `issuer_class`. Selectively disclosed: `legal_name`, `iban`,
  `ico`/`lei`.
- **KB-JWT** (key binding, signed by the `cnf` key): `aud = "AG1/<DEPLOY>/changes/<change_id>"`, `nonce = change_nonce`,
  `iat` ≤ 15 min old, `sd_hash`. Fail → `kb_jwt_invalid`.
- **Issuer classes** (2 of 3 **distinct** required): `supplier-erp` (supplier's own key, enrolled via a KYB pack),
  `supplier-bank` (account-holding bank; attests that the holder of IBAN Y **is** ICO/LEI X; from a pinned trust list),
  `registry` (registry witness signing ADIS/ARES/MostlyRight snapshot facts; never attests a foreign account).
- **Pinned trust list**: `registry.issuer_pins` = `[{issuer_class, iss, jwk_thumbprint, pinned_at}]`, set at supplier
  enrolment; the class is derived from the pinned key, never from the VC's own claim. Unpinned → `issuer_not_pinned`.
  No pins (`in_network = false`) → `break_glass_required` (callback path).
- **Verifier**: `executor.attest.vc.verify_vc(vc: str, change: dict, *, pins: list[dict], now: datetime) -> AttestResult`,
  `AttestResult = {ok, issuer_class, iss, error, disclosed {legal_name, iban, ico}, vc_sha256}`; `ok` requires the
  disclosed `iban == change.new_iban` and `ico == change.vendor_ico`. `error` is one of `kb_jwt_invalid`, `issuer_not_pinned`,
  `break_glass_required` (own HTTP codes, §4.4) or `binding_mismatch`, `vc_invalid`, `vc_revoked` (HTTP 403
  `attestation_insufficient` with `details.vc_error`). `issuer_class` comes from the matching pin, `null` when unpinned.
- **Revocation**: static list in the demo (`data/vc_status.json`); Token Status List later [U].
- **Commitments**: the `attest` log stores `SHA256(canonical_json(body) || commit_nonce_128)`, never a bare IBAN hash.
- The v1 EIP-191 `VENDOR_ATTEST` path is kept as the **hardware issuer profile** (ATTEST screen, §5.2), stretch.
- Library: `sd-jwt` 0.10.4 [API fit U]; fallback hand-rolled JWS + disclosures with `cryptography`.
