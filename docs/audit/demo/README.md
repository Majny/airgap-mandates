# Pre-sealed offline demo bundle

Generated by `make demo-bundle` (`python -m tools.demo_bundle`). The stage check is `make offline-demo`, which
runs `tools/offline_demo.sh docs/audit/demo` and needs no network ("Wi-Fi off").

## What is in here

| File | What it is | Checked by |
|---|---|---|
| `bundle.json` | Audit export (CONTRACTS §7.4) of one run of demo beat S1: a 2/2 mandate, three payments under the mandate, a fourth over the cap that is challenged and executed after an exact-sign step-up, then a refused replay. The log is ticked, so every leaf is covered by a cosigned checkpoint. | `python -m tools.verify_audit bundle.json --trust-keys trust-keys.json` (replay on) |
| `trust-keys.json` | The `log` and `w1` verifier keys (public only, signed-note vkey format). These are the pins: in a real deployment you get them out of band, not from the bundle. | used by every step |
| `receipt.json` | Self-contained receipt of the last executed payment (the step-up, 125000.50 CZK): ledger row, execution leaf, inclusion proof, cosigned checkpoint note. | `python -m tools.verify_audit --receipt receipt.json --trust-keys trust-keys.json` |
| `checkpoint.txt` | The latest cosigned checkpoint note (C2SP signed note). | `.local/bin/noteverify checkpoint.txt <log vkey> <w1 vkey>`, using only stock `golang.org/x/mod/sumdb/note` |
| `RED-BUNDLE.txt` | Present ONLY if the bundle was written with `--allow-red`: it lists the verifier problems still open. While it exists, the bundle is NOT sealed and must not be presented as green. | - |

## The stage check (`make offline-demo`)

1. Stock Go `sumdb/note` verifies the log signature on `checkpoint.txt` (prints `OK`). It reports the W1
   cosignature as `UNCHECKED`, because stock `note` does not know that signature type; step 2 checks it.
2. The verifier accepts the whole bundle with pinned keys and `decide()` replay on.
3. The verifier accepts the receipt with pinned keys.
4. One byte of one execution leaf (the last digit of `amount_minor`) is flipped in a temp copy; the verifier
   must go red and name that leaf (`seq N: leaf hash mismatch`).

Each step prints a PASS/FAIL banner; the script exits non-zero if any step fails. `make offline-demo` builds
`.local/bin/noteverify` first with `go build -mod=readonly` (from the Go module cache), so run it once while
still online to warm the cache.

## What is simulated

- Memory backend with a fixed clock (`2026-10-19T12:00:00Z`), not the AWS deployment the demo runs on.
- Signers are throwaway software keys enrolled for the run (not Trezor devices).
- The log and W1 Ed25519 keys are throwaway local keys created in a temp directory and deleted after the run;
  no private key is ever written here. Each regeneration therefore has new keys, new signer addresses and new
  tx ids; amounts, invoice numbers and the event sequence are the same.
- The payment rail is the simulated rail; vendors and invoices are fictitious.
